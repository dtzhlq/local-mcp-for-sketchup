## 目标与交付边界

让支持工具调用的普通模型通过 MCP 自身说明发现常用建模路径，减少猜参数、错误调用和无必要的后续操作。保留四个公开 Gateway 工具，复用已有参数构件、资产、原生外观及受审编辑能力。

本轮完成不等于证明“任意模型均能使用”、90%成功率、所有任务实机通过或跨平台发布通过。未充分验证的入口明确列为已实现/待实机或专家路径，失败不改成通过。

## 调整后的检查规则

1. 已通过且与本次改动无关的检查直接复用，不重复运行；已有实物和原生回读不因日期变化而作废。
2. 每次具体修复仅检查受影响契约。只改文案时审查文案；改短响应时检查字段与长度。不为凑覆盖率启动全量回归。
3. 日常建模在必要质量检查和成功保存后交付并结束。关闭重开、冷启动、再次修改只在用户明确要求持久化/恢复专项时执行；没有执行就保留对应证明为 false。
4. 未执行的新功能完整实机路径如实列出边界，不为了勾选本计划重复批准、建模、截图或保存。实机仅在交付本身需要，或现有证据不足以解决具体阻塞时使用；一次一个文档，用后关闭。
5. 三模型×基础/优化入口×完整正负例，以及未见变体、90%目标，移至后续可选量化专项，不纳入本轮剩余工作；不生成虚假的通过率。
6. 批准 authority、冻结要求、目标/来源保护、执行后必要原生检查、幂等与不确定时不重放等门禁保持。不得通过删除保护或修改历史结果来减少检查。
