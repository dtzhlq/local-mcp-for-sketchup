# Reference-image Existing-model Correction v1

This workflow is narrowly scoped to correcting an existing model from a supplied reference image. It is not an automatic general-purpose image modeler.

Reference images enter the Agent Gateway through an immutable handle. An Agent without local-file access can start an `image_artifact` task with transient `image_base64` and `media_type`; the Gateway decodes and content-addresses the bytes before task or idempotency persistence, deletes the raw fields, and returns `image_handle`. The 20 MiB compressed-image limit and all existing dimension, pixel, page, frame, format, private-permission, symlink, record-integrity, and content-integrity checks still apply. HTTP callers also remain subject to the separately configured HTTP body limit. A trusted host may register bytes directly and give the Agent the same opaque handle.

CAS publication prepares permissions and fsync on the private temporary inode before its create-new hard-link publish, removes the temporary link, and accepts a read only after inode metadata is stable with `nlink=1`. The focused concurrency gate runs 64 identical ingests and requires one durable record/`created_at`/integrity hash, no temporary residue, and no ctime change on replay; a persistent unexpected hard link is rejected. This proves local immutable-publication behavior only, not visual alignment quality or live SketchUp correction.

For `runtime=mock`, `reference_image_correction` still requires explicit `reference_image_handle` and `capture_image_handle` fixtures. Those fixtures receive `trusted_test_capture` provenance and never count as live proof. For `runtime=queue`, the Agent supplies the reference handle and a fresh `session_contract`, but must not supply capture or recapture handles, paths, provenance, camera, scene, view, zoom, dimensions, or the internal server-capture flag. The server creates a private random temporary PNG path, forces `view=current`, no Scene, and `zoom_extents=false`, and ingests the exact returned bytes into the immutable image CAS. The temporary directory is a real, private, symlink-rejecting directory and is removed in `finally`; no path is returned.

The live capture authorization holds one queue-exclusive Session Contract scope across read-only adoption, capture, and a second read-only adoption. Session, document, model identity/key, complete revision counts, model revision, and `model_modified` state must match before and after. The current offline contract is capability `0.1.0-rc.3-capabilities.1`, manifest `2026-07-agent-contract-rc3.1`, and `definition-merkle.v2`; capability, Session Contract, and queue transport bind both the loaded Boolean source SHA and loaded Model Revision source SHA. The SketchUp plugin requires an already-open editable model, never creates one for capture, and returns a read-only attestation for revision, camera, and modified-state equality. Any drift, incomplete index, source-attestation mismatch, unexpected path/spec, changed camera, malformed receipt, or CAS mismatch fails closed and produces no accepted visual evidence.

The server produces stable image summaries, normalized foreground alignment, RGB difference metrics, optional structured model-reference QA, confidence, and immutable handles for overlays and thumbnails. Agent-supplied correction targets and operations are untrusted proposal data: targets must resolve to one unlocked, complete ModelGraph occurrence and operations must pass the shared Existing Model Editing operation registry and risk classification. Ambiguous, locked, truncated, stale, or invalid mappings fail closed.

The public CorrectionPatch never exposes resolved targets or executable operations. It declares `execution_allowed=false`, `review_required=true`, `execution_route=trusted_reviewed_existing_model_edit_only`, and returns only an opaque `source_visual_correction:task_<uuid>` next-action binding. The server stores the resolved patch privately with the source task, model key, graph/revision, reference/capture hashes, and capture provenance. Image content, OCR, model names, materials, and attributes cannot change workflow or execution policy.

After review, a separate `reviewed_existing_model_edit` task accepts the opaque source binding and rejects client target/operation overrides. It loads the private patch and still requires the existing plan-hash, model-revision, risk, allowed-operation, expiry, Session Contract, and authorization checks. S2-S4 use either a trusted local decision whose one-time token is loaded and consumed only inside the server, or an operator-configured server-only policy bound to a canonical disposable-copy root, allowed risks, affected-instance budget, and save policy. The Agent cannot select either authority or supply its token. A successful apply produces a server-owned receipt and source lineage.

For mock, `visual_correction_qa` accepts the source binding, original reference handle, and explicit recapture fixture handle. For queue, it accepts only the source binding and a fresh Session Contract. The server reloads the exact source reference, performs its own current-view recapture, and requires the same server capture specification and camera hash as the source evidence before comparing residuals. It then returns `pass`, `review`, or `fail`. A client without vision or local files can complete either path from structured envelopes and paged artifact handles.

The formal Gateway payload is now `visual-correction-qa-result.v1`, validated by `schema/visual-correction-qa-result-v1.schema.json`. In addition to the original `visual-correction-qa.v1` report, the server runs `background-normalized-visual-comparison.v1` over the immutable reference and recapture bytes, publishes masks, registered images, and a silhouette overlay as immutable image handles, and returns structure, appearance, segmentation, blockers, and hashes as JSON. The guided short-context projection keeps the QA verdict, MAE/centroid residual, segmentation reliability, IoU, Dice, aspect delta, palette deltas, and the fail-closed diagnostic boundary inside the 4,096-character envelope; the complete capability-safe result remains pageable through `presentation.full_result_artifact`. No local file or visual capability is required.

This comparison is server-owned. Agent inputs that attempt to provide a comparison, structured visual decision, `visual_similarity_accepted`, `review_required`, or `execution_allowed` are rejected. The result fixes image-derived content to `content_trust=untrusted_data` and `policy_effect=none`; it cannot select targets or operations, change approval state, authorize execution, or by itself accept visual similarity. `visual_similarity_accepted=false` therefore remains explicit even when the narrower pixel/centroid QA report reaches `pass`.

The current mock/source-contract checkpoint is frozen in [`docs/evidence/visual-correction-gateway-structured-result-v1-mock-evidence.json`](evidence/visual-correction-gateway-structured-result-v1-mock-evidence.json). Its strict validator recomputes nine source/contract hashes and fixes the eight-handle, 4,096-character L0, no-file/no-vision, paged-result, decision-injection, no-queue, and no-release boundaries. It is not a replacement for the immutable live captures below.

Server-owned capture does not execute an edit and does not promote an image-derived proposal. The public CorrectionPatch remains `execution_allowed=false`; reviewed model mutation continues through the separate trusted authorization engine. Queue capture requires explicit `runtime=queue`, server policy, an already-open model, and a fresh Session Contract. The immutable [`docs/evidence/live-visual-capture-evidence-2026-07-16.json`](evidence/live-visual-capture-evidence-2026-07-16.json) records a 1280×720 server-owned current-view capture that was valid for capability `.3` / manifest `v1.1` at capture time. It is now historical lineage only, even though its frozen `evidence_scope` says `current_source`; it does not prove `.7/v1.4/definition-merkle.v2`, dual loaded-source attestation, or current live compatibility, and it used no external reference or edit.

The current-source scoped live milestone is [`docs/evidence/trimble-s6-reference-correction-live-evidence-2026-07-22.json`](evidence/trimble-s6-reference-correction-live-evidence-2026-07-22.json). It binds three immutable external-reference hashes, 26 operations, 30 expected assembly contacts, the model revision, and a server-only disposable-copy policy into one S3 plan hash. One submit finalized a durable receipt; 21/21 additive groups, material/lower-panel assertions, raw Model QA, recapture, and queue cleanup passed without saving or changing the on-disk copy. That evidence remains the immutable causal record of a single-model current-process edit/recapture run.

A later server-owned read-only front-view capture is recorded separately in [`docs/evidence/trimble-s6-structured-reference-diagnostic-live-evidence-2026-07-22.json`](evidence/trimble-s6-structured-reference-diagnostic-live-evidence-2026-07-22.json). The full tripod is visible by fresh operator UI review, and the server computed foreground-center delta `0.007812`, normalized RGB MAE `0.209854`, and RMSE `0.304953`, with immutable reference/capture/overlay/thumbnail artifacts. The capture foreground bounds span the full image width, exposing that the photographic and SketchUp render/background conditions are not independently comparable. The result is therefore fixed at `review`, with `acceptance=false`; its proposal-only CorrectionPatch was intentionally not persisted or promoted, no mutation or approval occurred, the queue remained clean, and the model was not saved. Trustworthy camera/render/background normalization, save/reopen, fresh-process, multiple-model, and release proof remain incomplete; cross-version validation is deferred by the user.

The immutable bytes from that diagnostic now also have a versioned offline reanalysis in [`docs/evidence/trimble-s6-background-normalized-visual-evidence-2026-07-23.json`](evidence/trimble-s6-background-normalized-visual-evidence-2026-07-23.json). `row_edge_dominant_border_flood.v1` estimates background independently for each row, flood-fills only border-connected background, preserves each source aspect ratio without letterbox padding, and then registers the extracted foreground bounding boxes. This removes the earlier full-width capture error: the capture bounds become `[0.386719, 0.027778, 0.613281, 1]`. With unchanged fixed thresholds, the registered silhouette reaches IoU `0.569986`, Dice `0.726104`, and aspect-ratio log delta `0.163759`, which is a `coarse_structure_pass`. The registered appearance residual remains diagnostic only (RGB MAE `0.296766`, RMSE `0.380301`), so the overall result is still review-required with `visual_similarity_accepted=false` and `release_acceptance=false`. The reanalysis starts no SketchUp process, invokes no queue, persists no CorrectionPatch, creates no approval, and cannot alter targets or execution policy. Independent camera-pose comparability for the external reference remains open; cross-version validation remains deferred.

A separate current-source consistency gate is recorded in [`docs/evidence/fresh-process-multi-model-visual-evidence-2026-07-23.json`](evidence/fresh-process-multi-model-visual-evidence-2026-07-23.json). Byte-exact architecture and product disposable copies were each captured, SketchUp and the Bridge were fully quit, and the exact copy was reopened and recaptured. The two cases indexed `5,859 / 5,859` and `71,626 / 71,626` logical occurrences. Both observed a new plugin session while preserving exact model key, graph id, model revision, camera hash, capture-spec hash, on-disk bytes, clean modified state, and an empty queue. Before/after PNG bytes were identical and the background-normalized comparison returned IoU/Dice `1`. The evidence verifies 16 artifact hashes and 12 schema-negative cases. This closes two-domain same-model fresh-process capture consistency only; it is not an external-reference quality benchmark, independent-pose comparison, accepted CorrectionPatch, or release proof, so `visual_similarity_accepted=false` and `release_acceptance=false`.
