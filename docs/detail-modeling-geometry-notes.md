# 详细建模几何能力与验证边界

本文描述 2026-09-06 这批实现的几何行为及离线验证范围。实时 SketchUp 验收以独立任务产物中的模型、原生几何证据和局部截图为准；本文及 mock 面数不构成实时验收。

## 管道和路径扫掠

`pipe_between_points` 与 `swept_path` 在 JavaScript 和 Ruby 中共用对应的路径网格算法。每个截面沿路径切线定向，截面方向由上一截面平行移动到下一截面。路径从水平转向竖直时不会因重新选择全局参考轴而突然转动截面接缝。空间路径不再固定使用 YZ 平面上的圆环。

内部节点切线采用相邻单位切线的角平分方向；首尾采用端部切线。相邻重复点和 180° 折返明确报错。重复首点表示闭合路径：采用连续首尾切线，按路径长度分配闭合残余扭转，共享接缝而不生成重叠端盖。开放路径生成端盖。

圆周分段支持 `chord_tolerance_mm`。分段下限由半径和弦高误差计算，可与显式 `segments` 合用；`max_segments` 是预算，默认 512，最大 4096。满足误差需要超出预算时失败，不悄悄降低精度。该约束控制圆截面的离散误差，**不负责把折线路径拟合成圆滑弯管**。现有折线的锐角、过大管径或自交仍可能造成局部碰撞；本次没有实现通用管道自交修复、真实圆弧弯头或 NURBS 曲面。

檐口排水配方另行明确构造了带孔折弯鞋：16 mm 竖直入口、约 75 mm 半径的 70° 圆弧采样与斜向出口。18 个截面保持 3 mm 壁厚，入口 40 段内外环与竖直落水管精确重合；2,880 个三角面组成闭合壁体，端部仅有环形收口，中心通道保持开放。该具体弯头通过数值拓扑、接缝和通道测试；它不是通用任意路径自交修复。

## 斜墙洞口和连续墙角

`wall` 的斜向分支先在局部 XZ 平面构造带真实洞口的板，再旋转和平移到端点。洞口偏移沿斜墙局部长度计量，厚度关于端点连线居中。旧轴向墙的单侧厚度和从最小坐标计算洞口的约定保留。端点基准高程必须相同；斜坡基线墙暂不支持。

`wall_path` 使用共享斜接截面的连续墙体网格。分段之间的内部端面删除，墙角顶点共用。洞口通过省略相应实体单元并保留洞边面构成，可以建造窗口与落地门洞；它们不再由修改面数和边数来模拟。

连续墙路径目前限定为水平开放折线。自交轮廓、零长度、反向转折和超出限制的锐角斜接会拒绝。洞口须位于一段墙的净直线范围内，不能跨过斜接墙角。`parapet_path`、`path_surface` 和其他围护宏不自动获得本次连续墙网格能力。墙体的外部放置在原生端按先旋转、后平移执行；这不代表整个旧版操作系统中的所有变换组合均已完成一致性审计。

## 装配和详细构件

PartGraph v2 显式区分叶子几何、装配子引用与场景根引用。只有标记为 `version: 2` 且提供 `roots`、`coordinate_system: part_local` 的图启用嵌套装配语义；v1 的父子描述语义保留。定义内仅编译支持的构造几何，不用运行时 `cut_*` 编辑操作补洞。

八类构件是窗、门、柜、水槽、扶手、墙节点、檐口排水和铺装。重复窗扇、抽屉、把手、扶手立柱、砖和篦子通过嵌套组件引用复用。柜体由独立板件及抽屉组成；水槽有独立盆壁、底部与排水孔；型材与篦子等使用带孔截面。模型是设计基准，不是现场测量结果或完整施工深化图。

组件引用的 `transform.mirror` 接受 `"x"`、`"y"`、`"z"` 或不重复轴数组。根和嵌套组件均按镜像负比例、Z 轴旋转、原点加平移的顺序放置；使用原生 `Geom::Transformation.scaling`，不复制或改名左右叶子。此支持只属于组件放置，不能推定所有旧版原语的 commonPlacement 都支持镜像。

厨房与入口立面的 baseline/edited 变体保留可追踪的部件 ID。厨房变体修改指定柜抽屉伸出量和把手材质；立面变体同步修改窗宽与五层宿主墙洞口，并修改门扇开启角。参数编译不会自动推断完整施工约束，其他尺寸组合仍需结构检查和局部视图检查。

## 根组件资产导入

`import_model` 的 `options.preserve_root: true` 对原生 SKP 采用保留根组件实例的路径。mock 对应路径把 JSON 模型的顶层几何完整放入新定义及根实例，重映射冲突的定义、材质、标签、图像引用和对象身份，同时更新嵌套实例引用。重复导入不覆盖已有组件定义或材质；缺失引用及循环失败不写入目标 session。旧 append 路径保持原语义。

导入模型的场景、全局相机和当前显示状态不会替换目标文档状态。mock 导入、目录登记和外部文件存在均不能证明 SKP 原生几何有效。资产目录包含八类构件和四类家具，保留来源与许可；许可未知不构成可使用证明。目录中 evidence/source/hash 都可编辑，`recorded_evidence_matches_file` 仅表示记录和当前 SHA-256 一致，不能据此返回 `native_geometry_verified: true`。文件修改、丢失或路径实际为目录会使匹配失效；真正原生验收仍需独立的模型打开与测量证据。

详细质量门应读取 SketchUp 实测面、边、叶子局部边界、材质和真实内环，不得以部件名称或 metadata 声明替代洞口证明。通用空腔和最小壁厚尚不能只凭已有证据完整证明；可以检查具体独立板件的实际尺寸与装配关系，再结合局部截图确认。通过以上离线检查后，仍需对相同定义和实例路径进行原生构建、测量及局部拍摄。
