# v0.4.1 中式古建与仿古建筑开发计划

日期：2026-10-03。目标版本：v0.4.1。本文保留当时的计划和基线；2026-10-05 已开始实施，当前实现与验收结果见 [开发记录](traditional-assembly-v041-status.md)，调用见 [通用装配说明](traditional-timber/ASSEMBLY.md)。

**本版重点是把已有的古建构件和通用建模能力接成可解释、可组合、可局部修改的语义装配入口，并改善常用视距下的屋顶、檐口和围护外观。** 固定五间殿堂是一个有来源的专用配方，不是项目可以建造哪些建筑的白名单。没有亭子或长廊预设，不能成为拒绝分解和建模的理由；但现有几何工具也不自动等于已经具备正确的转角、屋顶拼接和历史构造规则。

v0.4.1 的可交付范围为：一个直廊、一个单檐四柱方形攒尖亭、一个等高等宽的 90° 转角廊节点、两种基本入口表达，以及一个由这些能力和简单房屋单元组成的仿中式单进院落。目标是外形和可见构造关系可信，不要求施工级、结构验算或严格古籍复原。复杂类型允许降级为有说明的方案研究模型，不宣称自动生成任意古建筑。

2026-10-03 的规划任务只新增本文档；当时没有修改功能、版本号、安装包或发布状态。下文“本轮”“拟新增”和实施顺序保留其规划语境，实际实施结果以开发记录为准。

## 3. 产品范围与开发顺序

开发优先级为：**通用契约＋直廊 → 方亭 → 90° 转角廊 → 基本门头与围护 → 小院组合和未预设请求**。先用两种不同的屋顶拓扑证明通用层有效，再增加组合，不先扩大五间殿堂参数表。

| 范围 | v0.4.1 必须交付 | 本版明确边界 |
| --- | --- | --- |
| 柱网与间架 | 矩形柱网、非等宽开间数组、柱高/截面、梁额檩支承链、单层房屋单元 | 不承诺任意不规则梁架、完整升起侧脚制度；启用这些特征须选择有适用条件的规则 |
| 直廊 | 有限直线路径、按实际跨距分跨、两列柱、梁额檩、双坡屋面、檐下椽/板、可选栏杆或坐凳 | 默认工程尺寸和简化檐口；不默认套用殿堂铺作或宋尺 |
| 方亭 | 四柱方形平面、单檐四角攒尖、集中顶点和脊线、可见角部承托、可选坐凳栏杆 | 工程选定的仿中式形制；不是故宫实物复制，也不是完整雷公柱/榫卯复原 |
| 转角廊 | 同标高、同宽、90° 折线路径；一个明确的共用节点，屋顶交接、柱梁去重和檐口收边 | 内外角采用本版选定节点；任意锐钝角、曲廊、坡地错层、丁字/十字交汇留后续 |
| 门头 | 单开间有屋盖的柱梁式入口；墙体圆形/月洞开口作为第二种入口表达 | 两者由通用族组合；垂花门、牌楼、歇山门楼、重檐与雕刻不作为完整专用型交付 |
| 围护与小品 | 素墙/山墙、真实开口、双扇板门、规则格栅窗；栏杆、坐凳、踏步、花池/影壁的简单几何 | 常用比例和连接可信；不承诺所有棂格、彩画纹样、须弥座或石雕类型 |
| 院落 | 正房、厢房、倒座或南侧入口、廊/围墙、少量小品的单进组合；各建筑可独立寻址 | 仿中式方案表达；不是传统民居完整制度，也不自动推断地区、礼制、消防或排水设计 |
| 未预设请求 | 名称不在目录时仍能使用已有族或受限显式几何表达，保存参数与简化说明 | 只覆盖可由已有操作和连接规则成立的组合；复杂拓扑或关键资料缺失须明确降级 |

后续版本再考虑六/八角亭、歇山/卷棚/多檐屋顶、复杂廊网、独立明清与地方规则、完整转角铺作、细棂格和彩画、照片到构造的推断。优先新增经过反复实际使用的能力，不按建筑名称堆预设。

## 4. Agent、通用语义层与专用预设的分工

### 4.1 分工原则

- **Agent**：理解用途、尺度、朝向、场地关系、目标风格和参考；分解成构件族与连接；说明不确定处；选择相机并检查模型的实际效果。Agent 不凭自然语言直接宣布隐藏构造正确。
- **通用语义装配层**：校验参数与来源，求柱网/路径和支承坐标，生成一致的屋顶/檐口/围护，编译 PartGraph v2 与 safe JSON DSL，记录依赖及可修改来源。
- **专用配方**：提供冻结的规则选择、布局、默认值、装配模板和适用条件。它调用通用能力时仍保留自身规则版本；模板失配时转通用分解，不把近似输入塞进固定预设。
- **MCP/SketchUp**：执行既有权限与资源保护、创建和受控替换、真实模型读回和任务恢复。编译成功只说明可生成 DSL。

```mermaid
flowchart LR
    A[用户请求与参考] --> B[Agent 分解与规则选择]
    B --> C[通用语义装配计划]
    P[版本化专用配方] --> C
    C --> D[参数求解与连接检查]
    D --> E[PartGraph v2 和 safe JSON DSL]
    E --> F[既有 Gateway 与 SketchUp]
    F --> G[原生摘要和必要局部读回]
    G --> H[效果检查与指定根修改]
    H --> C
```

### 4.2 请求尚无预设建筑时的执行步骤

1. **发现实际能力**：通过 `start_agent_task(intent="discover")` 读取任务、参数、规则和运行时能力。将“没有完整配方”和“没有所需几何/连接能力”分别判断。
2. **提取已知输入**：建筑用途、平面或廊道路径、面阔/进深/柱高、屋顶形态、围护、材料、位置。缺少易纠正的工程尺寸可作明示选择；严格指定年代、关键形制或接入现有建筑而资料不足时，只澄清影响这些要求的信息。
3. **选择来源模式**：使用 `source_bounded`（匹配已有冻结规则）、`song_informed`（只用适用的宋式关系）或 `contemporary_chinese`（工程尺寸与仿中式构造）。后两者是拟新增模式，不是历史认证。宋式材份不是全部仿古建筑的默认尺寸体系。
4. **生成语义计划**：列出柱网/路径、构件族、连接端口、屋顶面和脊檐边界，给每个单元稳定 ID；显式列出采用的规则、推导和简化。名称“茶亭”“门廊”“庭院”不参与硬编码形制判定。
5. **参数化与预检**：依次求解布局、承托、梁檩、屋面、檐口、围护；检查连接方向、正尺寸、屋顶裁边、开口净宽、能力清单和资源估计。引用的族缺失时返回具体缺项及可行降级，不能把近似屋顶悄悄替代指定形制。
6. **编译与生成**：通用计划编译为 `includeReset:false` 的 PartGraph v2/DSL。继续使用 `preflight_model`、新鲜 `discover/connect`、`create_model`；保存稳定幂等键与任务 ID。专家 `inputs.code` 路线继续可用，但临时 DSL 没有受信来源时不能冒充可用公共参数编辑器管理的建筑。
7. **读回与效果检查**：检查实际根实例、主要装配、完整子树指纹、原生资源总量和同修订总览。关键接头通过限定实体的 `query_model_geometry` / `measure_model_geometry` 或相关局部查询核对；不可得时记为未核对，不用包围盒替代真实距离。
8. **局部修改**：从 `parameter_sources` 取得当前创建记录；选择实际顶层根与显式参数变更，经 `modify_design_parameters`、既有审阅和替换流程执行。对廊宽、某跨跨度或亭子起翘，仅重编译有关语义依赖并复用未变定义；再读回目标与受保护对象。
9. **保存结果与沉淀配方**：交付保存使用 `deliver_model`。成功一次先保留为用户项目计划；同类需求再次成功且参数语义稳定后，再抽取版本化配方。配方库的准入不成为通用建模的准入条件。

## 5. 拟新增的通用契约

### 5.1 输入、编译输出和持久化

保留现有 `kind:"traditional_timber"` 和五间预设行为；拟新增 `kind:"traditional_assembly"`，沿用原 Gateway 工具和 intents。不要用更换 `preset` 字符串来绕过旧规则约束。

`traditional-assembly.v1` 计划至少包含：

| 字段 | 必须表达的内容 |
| --- | --- |
| `id`、`version`、`mode` | 稳定身份、契约版本、来源模式 |
| `parameters` | 已解析的 mm/角度参数、非等跨数组、枚举和显式来源；保留外部尺/材份输入及其换算，内部统一 mm |
| `rule_bindings` | 每个规则包的 ID、版本、内容哈希；没有可靠条文的形制使用项目规则包 |
| `layout` | 矩形柱网或有 ID 的路径段；首轮路径限定直线与水平 90° 转角 |
| `assemblies` | 构件族、局部参数、实例、材料、端口和所属根；建筑名称只作语义说明 |
| `connections` | 两端语义 ID/端口、方向、接触或允许搭接关系、局部坐标和容差 |
| `parameter_bindings` | 参数到单元/连接的依赖关系；只允许受限参数引用和已实现的确定性推导，不执行自由表达式或任意脚本 |
| `simplifications`、`open_questions` | 可见省略、未知项、不可验证范围及降级理由 |
| `representation` | 瓦面、曲线分段、线条处理和表示版本；独立于历史规则版本 |

通用族统一接口拟为 `buildTraditionalFamily({family,id,parameters,ruleBinding})`，返回 `parts`、`root_id`、`materials`、`ports`、`dependencies`、`expected_values`、`provenance` 与 `signature`。`ports` 包含局部原点、轴向/法向、支承面或接合范围、接触语义及允许误差；端口既用于定位，也用于定义要核对哪种连接。

`compileTraditionalAssembly(plan)` 返回既有 bundle 结构：`part_graph`、`dsl`、`profile`、`detail_spec`、`views`，以及本版增加的连接清单、参数影响集和来源记录。生成器预期值保持 `rule_expected_values` 身份，与原生测量字段分开。

创建记录必须保存规范化计划、参数来源、族/规则/表示版本及哈希、逻辑 ID 到原生根的映射、材料映射和创建回执。规则或手工几何已改变时拒绝静默重编译；升级配方须有明确迁移路径，不能只沿用同名规则。

下面是拟新增的预检输入形状，**当前 v0.4.0 尚不接受它**。同一个 `inputs.task` 在预检通过后用于创建；执行时另加运行时、连接任务和幂等键。规则内容哈希由服务端解析并冻结，客户端声明不能替代核对。

```json
{
  "intent": "preflight_model",
  "inputs": {
    "task": {
      "version": 1,
      "kind": "traditional_assembly",
      "id": "corridor-a",
      "units": "mm",
      "parameters": {
        "bays_mm": [3000, 3000, 3000, 3000],
        "width_mm": 2000,
        "column_height_mm": 2800,
        "roof_rise_mm": 650
      },
      "placement": {"origin_mm": [0, 0, 0]},
      "assembly": {
        "version": 1,
        "mode": "contemporary_chinese",
        "rule_bindings": [{"id": "contemporary-chinese-v1", "version": 1}],
        "layout": {
          "kind": "path",
          "segments": [{"id": "run-a", "direction_deg": 0, "bay_lengths_parameter": "bays_mm"}],
          "width_parameter": "width_mm"
        },
        "assemblies": [
          {"id": "frame", "family": "path_frame"},
          {"id": "roof", "family": "roof_unit", "parameters": {"type": "gable"}},
          {"id": "eave", "family": "eave_unit"}
        ],
        "parameter_bindings": {
          "frame": {"column_height_mm": "column_height_mm"},
          "roof": {"rise_mm": "roof_rise_mm"}
        },
        "connections": [
          {"from": "frame.roof_support", "to": "roof.bearing_boundary"},
          {"from": "roof.eave_boundary", "to": "eave.roof_edge"}
        ],
        "representation": {"tile_detail": "surface"}
      }
    }
  }
}
```

M0 须把这些端口名、族默认值、容差和参数引用写成完整 schema/目录契约；上例只示范一个直廊的请求边界，不代替这个工作。参数编辑继续传 `creation_task_id`、`scope:"single"`、实际 `targets` 和 `changes:{"bays_mm":[3000,3300,3000,3000]}`，不重新发送创建 DSL。

### 5.2 没有专用族时仍可建模

计划允许一个受限 `explicit_geometry` 分支：使用当前能力表内的 `mesh`、带洞轮廓拉伸和基础形体，声明端口、参数绑定与来源，编入同一个装配契约。这样可以在尚无“花架”“小型景墙”专用配方时继续构造。显式几何仍接受 schema、命名、资源、修订和编辑权限检查，不接收可执行 Ruby/JS。

若关键外形必须依赖未实现的几何求解，返回 `needs_reference` 或 `unsupported_topology` 并保留已完成的布局/构件方案。若用户已允许外观近似，生成标记为 `approximate` 的简化方案；若用户要求的关键形制会改变，先给出具体替代内容，不能把用户未答复当成同意。

### 5.3 局部修改与场地组合的边界

现有参数编辑器仅支持明确的顶层组件根，不能把任意嵌套路径解释成单实例替换。v0.4.1 沿用这个边界：一座亭子或一条连续转角廊作为一个根；改变内部参数时替换该根的新定义，复用未变子定义。无需实现原生逐根椽子的实时增量编辑。

院落采用多个独立顶层建筑根和一个版本化 `scene_plan`。组合器负责布局、公共标高、连通关系和创建顺序；每个根保留自己的原创建任务，修改其中一房不会重放全院创建。跨根相接的廊段优先并入同一廊根；确需同时影响其他建筑时列出关联目标并走已有审阅流程。本版不承诺任意全场参数的一次原子联动或自动移动已有对象。

组合操作复用 `composeDesign` 的明确添加、实例变换、材料冲突及空腔映射机制，但其当前家具/配方枚举和场景编辑适配不能直接冒充古建通用接口；本版要补对应族与持久化适配。

## 6. 最小通用构件族与几何接口

| 构件族 | 首轮输入与连接 | 复用和新增重点 |
| --- | --- | --- |
| `frame_grid` / `path_frame` | 开间数组、进深、柱高/截面；路径段 ID、跨距、廊宽；输出柱脚、柱顶、梁檩支承点 | 复用 `solids.mjs` 梁、圆柱/管和组件；新求解器不依赖五间固定柱网 |
| `beam_purlin` | 起终点、截面、支承端口、方向 | 用统一支承坐标定位；局部轴稳定；隐藏榫卯以有说明的接触/局部搭接表达 |
| `roof_unit` | 支承边界、类型、举高/折线、出檐、角部参数；输出屋面采样、裁边、脊线、檐线 | 首轮双坡悬山外观、带山墙的硬山表达、方形攒尖；平面屋盖可作降级。四阿继续沿用旧预设，不据此承诺任意四阿或歇山 |
| `eave_unit` / `corner_junction` | 檐线、支承线、椽距/截面、板厚、出檐；直段及 90° 节点 | 屋面、椽飞、板件、瓦面共用采样和边界，避免各自曲线脱接；先解决节点归属、去重、内角收口，再做装饰 |
| `bracket_or_seat` | 柱头/梁檩端口；`none`、简化承托或适用的冻结宋式组合 | 廊亭可以不用斗栱；现代装饰性托臂不能冒称宋式铺作。转角不能叠加两套普通柱头铺作 |
| `enclosure_opening` / `joinery_panel` | 柱间净宽、高度、墙厚、开口形状、门扇/格栅、嵌入量 | 复用 `joinery.mjs` 的可分离几何及轮廓拉伸；规则格栅与真正圆洞，窗框与墙/柱不悬空；不直接挪用殿堂固定四窗布局 |
| `rail_seat` / `site_piece` | 明确路径/放置、尺寸、栏杆或坐凳、踏步/花池/影壁形体 | 基础几何与重复组件；优先可见轮廓和位置关系，复杂石雕等走有说明的简化 |
| `explicit_geometry` | 现有 shape 原语、参数引用、局部坐标、端口和来源 | 为未收录需求保留通用通道；不扩展任意代码执行能力 |

路径使用中心线和有向局部坐标；首轮 +Z 向上、跨段方向为局部 +X、横廊方向为 +Y。交点按语义节点归属去重，不凭浮点坐标字符串命名；跨距改变后柱、梁、檩、椽和围护同源更新。路径交叉、短段容不下节点、负净宽和失去支承的组合在生成前阻止。

屋顶族共享“面域＋采样函数＋边界类型”的接口。脊、檐、山墙和内角交线分别标识；没有定义交线的两块屋面不能直接穿插后宣告完成。90° 转角先固定一种可解释的拼接方式和容差，不把普通翼角函数当成凹角或廊道交汇求解器。

## 7. 外观与轻量表示的具体任务

### 7.1 先修影响识别的关系

视觉优先级为屋顶轮廓/比例、柱网节奏与承托、檐下连续性、门窗墙体关系、材料大色块，最后才是瓦片与脊饰细节。直廊不能只是长屋顶配柱；方亭不能把殿堂屋顶缩短；门头的门洞位置、墙体或柱梁关系要构成可辨认入口。

工程默认比例属于项目选定，并在参数来源里记录。屋顶下表面、椽飞和望板必须有相容坐标，禁止靠调相机、隐藏问题构件或增加装饰掩盖连接错误。材料先用现有木、灰瓦、砖/石和墙面声明；不为这一版增加大纹理包或独立渲染系统。

### 7.2 瓦面、组件和线条

1. 复用已有三种瓦面表示，不重复开发逐瓦引擎。拟新增通用场景默认 `surface`，檐口可显式选择少量 `light` 收边；`detailed` 仅在用户要求的近景单元启用。混合方式写入表示版本和参数，不做静默动态切换。
2. 同族同参数定义复用；瓦垄/短瓦段、重复椽和栏杆作为组件。记录唯一定义几何和展开实例估计两种数量，避免把少量定义误当成低资源占用。转角裁瓦和非仿射曲面保留真实局部几何，不能为了复用而拉歪形体或扩大原生包围盒。
3. 首选生成阶段省去多余的共面三角对角线；确需清理时仅处理新生成定义内部、两侧面共面且材料/语义连续的非边界线。保留自由边、开口边、屋脊/檐线、搭接唇边和组件接缝，不全模型删除边。
4. 现有 Ruby `soften_edges` 的 `coplanar` 模式处理两面共面线，`cad` 按相同 `cad_face` 标记柔化。它是柔化，不等于拓扑删除。新网格按连续表面分配标记，必要时只补局部保护条件；真实折线和不同材料边不作统一 `smooth:all`。
5. 开放表皮的 `surface/light` 不用于封闭体积、加工或结构断言。旧五间模型的规则与 `timber-render.v2` 继续固定；新通用表示独立版本化，旧记录不自动升级。

资源预检继续采用既有预算、操作数/实例数、队列与原生资源保护。**通用 Agent 输入不得自动继承固定可信预设的放宽上限。** 先让直廊、方亭和小组合落在正常预算内；若超限，说明预计成本并提供减瓦/减细节/拆根方案，不先提高限额。

正常开发只记录一次编译/创建/读回/修改耗时、面边实例计数及交付文件大小，不做帧率专题、参数矩阵或硬件对比。出现明显卡顿、堆内存失败或超预算时，再针对出问题的阶段加一项最小诊断。

5. **节点和可分发素材**：优先有平立剖的机构测绘/学术资料、用户自有照片和明确许可的 Commons 原始文件。网站可浏览不等于图片可随软件再分发；对未明确许可的参考，只记录链接与分析、自己绘制示意。原图/扫描/视频留本地研究目录，GitHub 只保留必要索引、规则、低体积自绘示意和参数输入。

| `test/traditional-assembly.mjs`（拟新增） | 单位/关键连接、来源绑定、影响集、越界保护与资源拒绝的少量检查 | 覆盖真实失败风险，不为每个尺寸和枚举写镜像测试 |

`src/product-modeling/parametric-recipe.mjs` 可增加新编译适配供本地复用；不要同时维护另一套直廊/亭子求解器。示例 runner 只有在调用 Gateway 明显重复时才新增，禁止把一次性研究脚本作为产品唯一入口。

## 10. 阶段里程碑、依赖与完成标准

估算为 10–15 个有效开发日，按顺序完成；资料等待和真实失败修复另计。阶段结束时根据实际难点调整剩余估算。以下是内部完成标准，不要求用户逐阶段重复批准，也不授权在本轮开始实施。

| 阶段 | 主要开发与依赖 | 可交付物和通过条件 | 估算 |
| --- | --- | --- | --- |
| M0 基线与契约 | main 基线核对；冻结最小参考、两个基础样例、参数/来源/端口契约 | 契约草案、项目规则与独立预期尺寸；识别新任务接入的特判和编辑适配点；原研究工作未受损 | 0.5–1 日 |
| M1 通用层与直廊 | M0；布局、梁柱、双坡屋面、檐口、创建记录及 Gateway 最小接入 | 直廊从通用计划经 MCP 生成/读回，改一次跨距成功；共享第二实例和参照物不变；这一闭环不能留到最后 | 2–3 日 |
| M2 不同屋顶的小建筑 | M1；方形攒尖面域、角部支承、脊/檐连续、坐凳栏杆 | 四柱方亭由同一语义层创建和读回；与直廊不共用固定整屋模板；总览/必要檐下视角可辨识承托和屋顶关系 | 2–3 日 |
| M3 转角与基本入口 | M1/M2；节点参考、90° 路径求解；墙洞/板门/格栅和基本门头组合 | 等高等宽 L 廊无重复节点、屋面收口连续；有屋盖入口与月洞入口实际几何不同；在后续组合中验收，不另建逐件原生测试工程 | 2–4 日 |
| M4 场地组合与泛化 | M3；组合计划、各根来源与任务映射、未预设分解与降级 | 一个小院场景经公共流程生成；一次只改廊/门头参数；其余建筑和参照物不变；未知名称能组合，未知关键拓扑有明确缺项和降级结果 | 2–3 日 |
| M5 开发交付收尾 | 前述最小检查通过；文档、输入配置、版本/迁移说明 | 可执行源代码与轻量示例、简短验收记录、未完成边界；核对 diff 只含有关内容。是否打包发布是后续独立任务 | 0.5–1 日 |

若 M2 发现统一屋面接口不能成立，先修接口而不是再写一个独立方亭脚本。若 M3 的复杂内角使资源或连接失控，保留直廊/方亭成果并报告该节点尚未达成；不能删除转角范围后把原 v0.4.1 目标报告为全部完成。

## 11. 最小验收集

所有尺寸均为本计划选定的工程试件，不是历史规定。自动检查预期值从以下输入与独立示意推导；不直接读生成结果当预期。

| 场景 | 输入和唯一必要变化 | 要发现的错误 |
| --- | --- | --- |
| A 直廊 | 长 12,000 mm，廊宽 2,000 mm，四跨各 3,000 mm，柱高 2,800 mm；第二跨改为 3,300 mm。同场放一份共享根及一个参照物 | 基准两列各五柱；新总长 12,300 mm。柱梁檩、屋顶、檐下及栏杆联动；改的是选中根；共享副本、参照物、原定义和目标放置不被误改 |
| B 方亭 | 3,600×3,600 mm，四柱，柱高 2,800 mm，单檐攒尖；举高/出檐是显式项目参数 | 四角屋面共顶、脊檐连续；柱梁与角部支承成立；瓦面/檐下不脱接；无套用殿堂网格的额外柱或屋脊 |
| C 小院组合 | 使用已有直廊/亭、少量双坡房屋单元和基本入口；含一个 90° L 廊、月洞开口和少量小品，首轮最多八个独立建筑/构件根 | 转角无重复柱/断檐/大片穿插；门窗洞真实开放；房廊标高和必要通道关系合理。只改廊宽或门头净宽一次，非目标建筑根与参照物不变 |
| D 未预设请求与降级 | 不新增“茶亭展示廊”配方，要求“方亭接带坐凳的廊，旁设月洞景墙”；复用 C 的构件形成参数计划。另要求同位置的双层六角歇山亭 | 前者由族、端口和参数组合，无硬编码类型专用入口；后者指出本版屋顶/层级求解缺项，输出简化方案或待参考计划，执行标志准确，不能宣称已生成完整指定形制 |

A、B 各检查一次实际模型。C 使用已有定义和配置，完成一次组合检查及一次指定根修改。D 首轮先做离线计划/预检与降级检查；没有引入新几何能力时不要求再建一座独立原生样例。未预设通用计划若最终采用新的显式几何，则只在 C 的相关局部补一个实际读回。

### 11.1 只保留能发现问题的检查

- **编译/规则**：单位换算；A 的柱线、长度和关键支承点；B 的共同顶点/边界；一个零尺寸拒绝；一个不相容连接拒绝。数组、版本/哈希和依赖的检查覆盖实际使用格式，不做组合穷举。
- **修改保护**：一次指定根变更，对共享副本和场地参照核对完整子树指纹；手工修改导致基线不一致时，必须在写入前拒绝。拓扑变更使 ID/映射不能安全继承时给出重建计划，不假装普通标量调参。
- **连接**：每个基础模型选一个实际承托关系；C 选一个转角交接和一个真实门洞/通道。使用限定几何查询核对实际距离或开口，不进行整屋逐面碰撞，也不把正常搭接当全部禁相交。
- **资源**：每个实际创建记录原生面/边/实例总量及预检估计；一个小型超预算输入在写入前拒绝。资源是保护门槛，不设新的帧率验收专题。
- **线条**：一个小网格检查内部共面线可省去/柔化，真实折线、开口和不同材料边仍在；优先离线夹具。只有 Ruby/native 路径发生变更才补一项原生或 Ruby API 形状检查。
- **失败恢复**：创建/替换继续使用原幂等键和任务 ID、回执 ledger。只有修改了恢复适配时，补一个提交后收尾失败的最小模拟，确认 resume 不重复写入；不故意反复令大型 live 模型超时。

原生视图默认每个 A/B/C 场景一张总览；选定接头或门洞在总览不可见时，最多补一张相关视角，只有实际问题才增加。同一参数修改后的图仅在判断变化需要时获取，不逐构件截图。

针对新通用层运行拟新增的 `node test/traditional-assembly.mjs`。改到旧规则/定义复用时再运行已有 `test/traditional-timber-rules.mjs`；改到摘要或恢复时分别运行 `test/assembly-summary.mjs`、`test/assembly-commit-recovery.mjs`。若改 Ruby 资源/替换接口，只补其对应的既有检查。以上命令以实施 checkout 的实际文件为准；不运行无关全仓测试。

### 11.2 验收证据与交付目录

开发输出建议放入 `output/traditional-assembly/v041/<run-id>/`，每次使用新目录，保存输入计划/解析参数、编译 bundle、任务 ID/回执、实际摘要/必要测量、少量图像和一份简短结果。模型仅在交付需要时保存，记录文件路径和哈希。

**本版不安排保存关闭重开、逐构件原生体检、大规模参数矩阵或性能专项。** 保存用于交付；不把它当成持久化验证。发现实际持久化问题时再增加与问题直接相关的一项检查。预检、mock、CI、原生几何、视觉结果和交付保存分别报告，不能互相替代。

原生通过至少要求：目标根和主要装配存在且可见、修订/指纹完整、选定连接与开口检查成立、受保护对象不变、资源在预算内，以及 A/B/C 的整体效果没有明显断接、悬浮、穿插或错误屋顶拓扑。复杂隐藏构造保持明确的未核验状态。

## 12. 风险、处理方式与版本边界

| 风险 | 具体处理 | 边界 |
| --- | --- | --- |
| 以旧研究分支代替产品基线 | M0 从 main/发布对象核对接口；保留当前分支 6 个本地提交和研究资料 | 本轮不切分支、不搬功能、不升级版本 |
| 专用殿堂代码与几何混在一起 | 抽取毫米几何/瓦面辅助函数，布局/规则单独适配；旧预设输出和来源继续稳定 | 不为了复用而改写已有宋式解释 |
| 屋顶好看但檐下连接错误 | 面域、梁檩与檐部同源坐标；一个原生承托检查＋必要视角 | 隐藏榫卯与完整构造认证不在本版 |
| 转角廊屋面相穿或内角收口失败 | 首轮限定一个同标高等宽 90° 节点，记录交线及裁边；失败只修节点 | 任意角度、错层与多路交汇后续处理 |
| 宋式规则被当成通用古建制度 | 来源模式、适用条件和四类依据逐项保存；现代比例明确归项目选定 | 明清/地区规则有独立资料才启用 |
| 通用计划只有创建、无法再编辑 | M1 即接公共来源记录和指定根调参；检查 `sourceDetails` 等固定目录适配 | 不把专家临时 DSL 自动纳入公共参数编辑 |
| 参数重建覆盖用户修改或共享实例 | 完整子树指纹、明确根/关联目标、新定义替换、旧定义保留 | 不清空模型、不原地改共享定义、不降低审批策略 |
| 瓦面/读回失控 | surface 优先、定义复用、普通预算、主要装配摘要＋小范围几何查询 | 不继承大殿预设宽松额度，不做全树叶节点展开 |
| 超时后重复创建或误清保护锁 | 原任务恢复、可信提交回执先持久化；结果未知先只读核对 | 不换键重放，不自动删除队列锁 |
| 资料不足或授权不明 | 只阻塞该规则/分发内容；继续明确工程选择的模块；自绘示意、链接引用 | 不复制受保护 Ruby、未授权模型或图片包 |
| 范围再次扩成完整古建库 | 以 A/B/C/D 和本版接口为完成边界；复杂需求先指出缺项 | 单个场景通过不宣称任意古建可生成 |

所有参数/默认值的依据用四类标记：`documented`（文献规定，定位到版/卷叶）、`derived`（由明确关系推导，保留输入）、`selected`（用户或项目选定）、`simplified`（为表达省略/近似，说明影响）。选择了文献参数的工程实长仍须单独标记，不能把示例 300 mm 尺或任意材份实长写成唯一历史常数。

v0.4.1 的完成边界是通用装配入口、上述最小族与受限组合、来源/参数持久化、指定根修改、轻量外观及极简验收。历史精度认证、复杂屋顶/廊网、完整彩画雕刻、结构计算、施工图、全场智能布局和任何类型的一键复原均不在这一版承诺中。
